# Status

Implemented and tested:

- `oxbloom-core`: `HttpMethod`.
- `oxbloom-macros`: `#[controller]`, `#[get]`, `#[post]`, `#[put]`, `#[patch]`, `#[delete]`, `#[head]`, `#[options]`, `#[component]`, `#[configuration]`, `#[bean]` (with condition options), `#[auto_configuration]`.
- `oxbloom-web`: router, Hyper server, graceful shutdown with a timeout, the ordered `Filter` layer, `HttpError` and problem+json error answers, forwarded-header handling, and with the default feature `json` the `Json<T>` response, `Request::json` and `Accept` negotiation, and with no feature a CORS filter, static resources (disk and embedded) and, with the default feature `compression` (gzip, brotli, zstd), a compression filter; see [Errors and filter order](09-errors-and-filter-order.md#errors-and-filter-order), [JSON and content negotiation](10-json-and-content-negotiation.md#json-and-content-negotiation), [CORS](11-cors.md#cors), [Compression](12-compression.md#compression) and [Static resources](13-static-resources.md#static-resources).
- `oxbloom-di`: singleton container with trait and collection injection, `primary`/`order`, lifecycle hooks and shutdown, lazy beans, `bean` factories, `#[configuration]`/`#[bean]`, profile conditions, and conditions on beans and groups with a conditions report.
- `oxbloom-config`: TOML files with imports, profiles and groups, environment and command-line sources, relaxed keys, lists, `Duration`/`DataSize`, placeholders, key migration, origins, serde binding, `Secret`, and `Config` as the property source of conditions.
- `oxbloom-security`: filter chain, deny-by-default authorization, JWT resource server with static keys and JWKS, and password login (slice 6a): `PasswordEncoder` with Argon2id and the `{id}hash` format, `UserDetails`, an in-memory `UserDetailsService`, `DaoAuthenticationProvider` and HTTP Basic on `HttpSecurity`. See [Password login](19-password-login.md#password-login). Sessions (slice 6b): `Session`, `SessionFilter` with a server-side `SessionStore` (`InMemorySessionStore`) or the stateless AES-256-GCM `CookieSessionBackend`, and the `security.session` keys; see [Sessions](20-sessions.md#sessions). Form login (slice 6c): `HttpSecurity::form_login`, a login and a logout handler, the `Authentication` kept in the session, a saved request, a default login page and the `security.form-login` keys; see [Form login](21-form-login.md#form-login). CSRF protection (slice 6d): a synchronizer token in the session, `HttpSecurity::csrf`, `CsrfConfig`, `CsrfToken`, `RequestSessionExt::csrf_token` and the `security.csrf` keys; see [CSRF protection](22-csrf.md#csrf-protection). Session management and security headers (slice 7a): `HttpSecurity::headers`, `HeadersConfig`, `HttpSecurity::session_limit`, `HttpSecurity::revalidate`, `HttpSecurity::clock`, `PrincipalSessions`, `SessionSummary`, `SessionRegistry` (in-memory store only) and the `security.headers.*`, `security.session.max-sessions-per-user` and `security.session.revalidate-interval` keys; see [Session management and security headers](23-session-management.md#session-management-and-security-headers). Remember-me (slice 7b): a signed cookie bound to the password hash that logs a user in again after the session is gone, `HttpSecurity::remember_me`, `RememberMe`, `Authentication::is_remembered`, `AuthorizationRule::FullyAuthenticated` (`fully_authenticated()`), the enforced reserved session key prefix (`SessionError::ReservedKey`) and the `security.remember-me.*` keys; see [Remember-me](24-remember-me.md#remember-me).
- `oxbloom-boot`: `OxbloomApplication` with lifecycle events, `ApplicationArguments`, application and command-line runners, ordered services with a shared stop deadline, Ctrl-C and SIGTERM handling, `ShutdownHandle`, exit codes, a banner, failure analyzers with a startup failure report, and auto-configuration with ordering, `exclude` and the conditions report. Feature `web` adds `WebServer`, the port-in-use analyzer and `WebServerAutoConfiguration`; feature `security` adds the security analyzer, a built-in analyzer for invalid `security.jwt` configuration, `JwtDecoderAutoConfiguration`, `PasswordEncoderAutoConfiguration`, `SecurityAutoConfiguration` and the `SecurityCustomizer` trait; feature `logging` installs the `oxbloom-logging` subscriber, registers the `LoggingSystem` bean, logs startup events and adds a built-in analyzer for invalid `logging` configuration; feature `ssl` adds `SslAutoConfiguration`, `WebServer::with_ssl` and a built-in analyzer for SSL bundle errors. `PropertyMetadata` and `boot_properties()` describe the configuration keys, and `auto_configurations()` lists the auto-configurations of the enabled features.
- `oxbloom-logging`: a `tracing` subscriber built from the `logging.*` keys, with levels, groups, console format and color, rotating file output, JSON lines with configurable fields, the `log` bridge and `LoggingSystem` for changing levels at runtime (the request logging filter lives in `oxbloom-web`); see [Logging](07-logging.md#logging).
- `oxbloom-test`: test support for applications: `ContextRunner` runs a context through the real boot lifecycle, with captured output, temporary config directories and controllable clocks (`FixedClock`, `ManualClock`); the `Clock` trait in `oxbloom-core` reaches JWT `exp`/`nbf` checks and the JSON log timestamp. With the feature `web`, `TestClient` sends requests to an `App` in memory or over HTTP/1.1 and `TestApp` starts a whole application with a real web server on port 0. See [`oxbloom-test`](../API.md#410-oxbloom-test).
- `oxbloom-ssl`: named SSL bundles from PEM (files or inline) and PKCS#12, reloaded by polling their files, with certificate validity warnings. With the feature `ssl` of `oxbloom-boot` the web server serves HTTPS from `server.ssl.bundle` (`App::serve_tls` in `oxbloom-web`, feature `tls`) and the JWKS fetcher can use a bundle through `security.jwt.jwks-ssl-bundle`; `TestClient::connect_tls` in `oxbloom-test` (feature `tls`) tests HTTPS. See [SSL bundles](16-ssl-bundles.md#ssl-bundles).
- `oxbloom-actuator`: health, liveness and readiness, build and platform info and log level endpoints on the application's web server, with `HealthIndicator` and `InfoContributor` beans, a certificate validity indicator and a `build.rs` helper for build info. With the feature `actuator` of `oxbloom-boot`, `ActuatorAutoConfiguration` wires them and flips readiness at `ready` and `stopping`. See [Actuator](17-actuator.md#actuator).
- `oxbloom-tasks`: scheduled tasks with `#[scheduling]` and `#[scheduled]`: cron expressions (six fields, Spring day-of-week numbers, IANA zones with daylight saving rules), fixed rate and fixed delay, a `Scheduler` with skip on overlap, a concurrency bound and a bounded shutdown. With the feature `tasks` of `oxbloom-boot`, `TasksAutoConfiguration` runs the tasks of every `dyn Scheduling` bean as a service that starts after the web server. See [Task scheduling](18-tasks.md#task-scheduling).
- `oxbloom-tasks` retry: `#[retryable(..)]` runs an async method again when it returns `Err`, with fixed or exponential backoff, jitter and a `retry_if` filter; the `tasks.retry.*` keys set the process-wide defaults through `RetryAutoConfiguration`. See [Retry](18-tasks.md#retry).
- `oxbloom-cli`: `oxbloom new` (a project started through `OxbloomApplication`), `oxbloom list`.
- `examples/hello`: a small application that uses the features above; see [Example](14-example.md#example).
- `examples/todos`: a CRUD REST API on the web, security and logging stack, with an admin route behind HTTP Basic, a visit counter in the session, a form login page with CSRF tokens, a limit of two sessions per user, `POST /me/logout-everywhere` and remember-me with a development secret; see [Example](14-example.md#example).

Everything else in `IDEA.md` is not started. See [Roadmap](25-roadmap.md#roadmap).
