# Status

Implemented and tested:

- `oxbloom-core`: `HttpMethod`.
- `oxbloom-macros`: `#[controller]`, `#[get]`, `#[post]`, `#[put]`, `#[patch]`, `#[delete]`, `#[head]`, `#[options]`, `#[component]`, `#[configuration]`, `#[bean]` (with condition options), `#[auto_configuration]`.
- `oxbloom-web`: router, Hyper server, graceful shutdown with a timeout, the ordered `Filter` layer, `HttpError` and problem+json error answers, forwarded-header handling, and with the default feature `json` the `Json<T>` response, `Request::json` and `Accept` negotiation, and with no feature a CORS filter, static resources (disk and embedded) and, with the default feature `compression` (gzip, brotli, zstd), a compression filter; see [Errors and filter order](09-errors-and-filter-order.md#errors-and-filter-order), [JSON and content negotiation](10-json-and-content-negotiation.md#json-and-content-negotiation), [CORS](11-cors.md#cors), [Compression](12-compression.md#compression) and [Static resources](13-static-resources.md#static-resources).
- `oxbloom-di`: singleton container with trait and collection injection, `primary`/`order`, lifecycle hooks and shutdown, lazy beans, `bean` factories, `#[configuration]`/`#[bean]`, profile conditions, and conditions on beans and groups with a conditions report.
- `oxbloom-config`: TOML files with imports, profiles and groups, environment and command-line sources, relaxed keys, lists, `Duration`/`DataSize`, placeholders, key migration, origins, serde binding, `Secret`, and `Config` as the property source of conditions.
- `oxbloom-security`: filter chain, deny-by-default authorization, JWT resource server with static keys and JWKS, and password login (slice 6a): `PasswordEncoder` with Argon2id and the `{id}hash` format, `UserDetails`, an in-memory `UserDetailsService`, `DaoAuthenticationProvider` and HTTP Basic on `HttpSecurity`. See [Password login](19-password-login.md#password-login). Sessions (slice 6b): `Session`, `SessionFilter` with a server-side `SessionStore` (`InMemorySessionStore`) or the stateless AES-256-GCM `CookieSessionBackend`, and the `security.session` keys; see [Sessions](20-sessions.md#sessions). Form login (slice 6c): `HttpSecurity::form_login`, a login and a logout handler, the `Authentication` kept in the session, a saved request, a default login page and the `security.form-login` keys; see [Form login](21-form-login.md#form-login). CSRF protection (slice 6d): a synchronizer token in the session, `HttpSecurity::csrf`, `CsrfConfig`, `CsrfToken`, `RequestSessionExt::csrf_token` and the `security.csrf` keys; see [CSRF protection](22-csrf.md#csrf-protection). Session management and security headers (slice 7a): `HttpSecurity::headers`, `HeadersConfig`, `HttpSecurity::session_limit`, `HttpSecurity::revalidate`, `HttpSecurity::clock`, `PrincipalSessions`, `SessionSummary`, `SessionRegistry` (in-memory store only) and the `security.headers.*`, `security.session.max-sessions-per-user` and `security.session.revalidate-interval` keys; see [Session management and security headers](23-session-management.md#session-management-and-security-headers). Remember-me (slice 7b): a signed cookie bound to the password hash that logs a user in again after the session is gone, `HttpSecurity::remember_me`, `RememberMe`, `Authentication::is_remembered`, `AuthorizationRule::FullyAuthenticated` (`fully_authenticated()`), the enforced reserved session key prefix (`SessionError::ReservedKey`) and the `security.remember-me.*` keys; see [Remember-me](24-remember-me.md#remember-me). Method security (slice 8): `#[method_security]` with `#[pre_authorize]`, `#[post_authorize]`, `#[pre_filter]` and `#[post_filter]` (typed rules, no expression language, woven at compile time), `AccessDenied` (401 for an anonymous caller and 403 otherwise through `HttpError`), the task-local `SecurityContext::current` and `SecurityContext::scope` that the chain sets for every request, `oxbloom_security::spawn`, and no configuration keys; see [Method security](25-method-security.md#method-security). OAuth2 and OpenID Connect login (slice 9 part B, feature `oauth2`): the authorization code flow with PKCE for OpenID Connect providers (discovery, id tokens signed with RS256, RS384, RS512, ES256 or ES384) and plain OAuth2 providers (user info), `HttpSecurity::oauth2_login`, `OAuth2Login`, `OAuth2Settings`, the `security.oauth2.client.*` keys, the login kept in the form login session and the tokens stored in the session; with the feature `oauth2` of `oxbloom-boot`, `SecurityAutoConfiguration` configures it from the keys and `security.oauth2.base-url`, and `FakeProvider` in `oxbloom-test` (feature `oauth2`) tests it; see [OAuth2 login](27-oauth2-login.md#oauth2-login). The OAuth2 client (slice 9 part C, feature `oauth2`): `OAuth2Client` with client credentials tokens in a per-registration cache (`client_credentials`, `invalidate_token`), the logged-in user's tokens from the session with the refresh token grant (`access_token_for`, serialized per refresh token with a record of recent rotations), and the interceptors `ClientCredentialsInterceptor`, `BearerRetryClient` (one retry after a 401) and `UserTokenInterceptor`; with the feature `oauth2` of `oxbloom-boot`, `OAuth2ClientAutoConfiguration` registers the client bean for the `security.oauth2.client.*` registrations; see [OAuth2 client](28-oauth2-client.md#oauth2-client).
- `oxbloom-boot`: `OxbloomApplication` with lifecycle events, `ApplicationArguments`, application and command-line runners, ordered services with a shared stop deadline, Ctrl-C and SIGTERM handling, `ShutdownHandle`, exit codes, a banner, failure analyzers with a startup failure report, and auto-configuration with ordering, `exclude` and the conditions report. Feature `web` adds `WebServer`, the port-in-use analyzer and `WebServerAutoConfiguration`; feature `security` adds the security analyzer, a built-in analyzer for invalid `security.jwt` configuration, `JwtDecoderAutoConfiguration`, `PasswordEncoderAutoConfiguration`, `SecurityAutoConfiguration` and the `SecurityCustomizer` trait; feature `logging` installs the `oxbloom-logging` subscriber, registers the `LoggingSystem` bean, logs startup events and adds a built-in analyzer for invalid `logging` configuration; feature `ssl` adds `SslAutoConfiguration`, `WebServer::with_ssl` and a built-in analyzer for SSL bundle errors; feature `oauth2` adds OAuth2 login from the `security.oauth2.*` keys to `SecurityAutoConfiguration`, a built-in analyzer for them and `OAuth2ClientAutoConfiguration`, which registers the `OAuth2Client` bean. `PropertyMetadata` and `boot_properties()` describe the configuration keys, and `auto_configurations()` lists the auto-configurations of the enabled features.
- `oxbloom-logging`: a `tracing` subscriber built from the `logging.*` keys, with levels, groups, console format and color, rotating file output, JSON lines with configurable fields, the `log` bridge and `LoggingSystem` for changing levels at runtime (the request logging filter lives in `oxbloom-web`); see [Logging](07-logging.md#logging).
- `oxbloom-test`: test support for applications: `ContextRunner` runs a context through the real boot lifecycle, with captured output, temporary config directories and controllable clocks (`FixedClock`, `ManualClock`); the `Clock` trait in `oxbloom-core` reaches JWT `exp`/`nbf` checks and the JSON log timestamp. With the feature `web`, `TestClient` sends requests to an `App` in memory or over HTTP/1.1 and `TestApp` starts a whole application with a real web server on port 0. See [`oxbloom-test`](../API.md#410-oxbloom-test). With the feature `security`, `with_authentication` runs a future with a given caller, for tests of [method security](25-method-security.md#method-security) without HTTP.
- `oxbloom-ssl`: named SSL bundles from PEM (files or inline) and PKCS#12, reloaded by polling their files, with certificate validity warnings. With the feature `ssl` of `oxbloom-boot` the web server serves HTTPS from `server.ssl.bundle` (`App::serve_tls` in `oxbloom-web`, feature `tls`) and the JWKS fetcher can use a bundle through `security.jwt.jwks-ssl-bundle`; `TestClient::connect_tls` in `oxbloom-test` (feature `tls`) tests HTTPS. See [SSL bundles](16-ssl-bundles.md#ssl-bundles).
- `oxbloom-actuator`: health, liveness and readiness, build and platform info and log level endpoints on the application's web server, with `HealthIndicator` and `InfoContributor` beans, a certificate validity indicator and a `build.rs` helper for build info. With the feature `actuator` of `oxbloom-boot`, `ActuatorAutoConfiguration` wires them and flips readiness at `ready` and `stopping`. See [Actuator](17-actuator.md#actuator).
- `oxbloom-tasks`: scheduled tasks with `#[scheduling]` and `#[scheduled]`: cron expressions (six fields, Spring day-of-week numbers, IANA zones with daylight saving rules), fixed rate and fixed delay, a `Scheduler` with skip on overlap, a concurrency bound and a bounded shutdown. With the feature `tasks` of `oxbloom-boot`, `TasksAutoConfiguration` runs the tasks of every `dyn Scheduling` bean as a service that starts after the web server. See [Task scheduling](18-tasks.md#task-scheduling).
- `oxbloom-tasks` retry: `#[retryable(..)]` runs an async method again when it returns `Err`, with fixed or exponential backoff, jitter and a `retry_if` filter; the `tasks.retry.*` keys set the process-wide defaults through `RetryAutoConfiguration`. See [Retry](18-tasks.md#retry).
- `oxbloom-http-client`: the outbound `HttpClient` trait with `Request` and `Response`, `ReqwestClient` (rustls on `aws-lc-rs`, a 10 second timeout, a 1 MiB body limit, no redirects, HTTP/1.1 only), `RetryingClient` for idempotent requests (feature `retry`), `InterceptedClient`, the `http.client.*` keys (feature `config`), `HttpClientAutoConfiguration` in `oxbloom-boot` (feature `http-client`) and `MockHttpClient` in `oxbloom-test` (feature `http-client`). The JWKS fetcher of `oxbloom-security` now runs on it. See [HTTP client](26-http-client.md#http-client).
- `oxbloom-data`: pooled SQL on `sqlx` for PostgreSQL, MySQL (and MariaDB) and SQLite, with the cargo features `postgres`, `mysql`, `sqlite` and `retry`: the `data.*` keys, `DataSources` (lazy pools for a default and named sources), `transaction` with savepoints, isolation and read-only options per driver, `transaction_with_retry` and `RetryableError`, fixed error text without URLs or passwords, and TLS from SSL bundles (`SslBundle::trust_pem` and `identity_pem` in `oxbloom-ssl`). With the features `data-postgres`, `data-mysql` and `data-sqlite` of `oxbloom-boot`, `DataAutoConfiguration` registers the registry, the default pool bean and `DataService`, which connects at start and closes at stop; with `actuator`, `DataHealthIndicator` reports `db` and `db.<name>`. `TestDatabase` in `oxbloom-test` (feature `data`) and `make test-db` test against SQLite, PostgreSQL and MySQL. No migrations yet (M3b), no ambient transactions and no repository layer. See [Data](29-data.md#data).
- `oxbloom-cli`: `oxbloom new` (a project started through `OxbloomApplication`), `oxbloom list`.
- `examples/hello`: a small application that uses the features above; see [Example](14-example.md#example).
- `examples/todos`: a CRUD REST API on the web, security and logging stack, with an admin route behind HTTP Basic, a visit counter in the session, a form login page with CSRF tokens, a limit of two sessions per user, `POST /me/logout-everywhere`, remember-me with a development secret and `DELETE /api/admin/done`, which calls the service method `TodoAdmin::purge_done` secured with `#[pre_authorize(role = "ADMIN")]`; see [Example](14-example.md#example).

Everything else in `IDEA.md` is not started. See [Roadmap](30-roadmap.md#roadmap).
