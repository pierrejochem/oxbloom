# ADR NNNN: The decision as a short sentence

- **Status:** Proposed
- **Date:** YYYY-MM-DD
- **Source:** a relative link to the design spec, for example
  `[C7 SSL bundles design](../superpowers/specs/2026-11-14-ssl-bundles-design.md)`, and, if useful, to
  the plan in `../superpowers/plans/`

## Context

What problem or force made a decision necessary? Name the constraints, the earlier decisions it builds on
(link them as ADR NNNN) and, when this record replaces an earlier one, say which one and why.

## Decision

What was decided, stated in a few sentences. Name the concrete types, keys, limits and dependencies, so a
reader can find the code.

## Consequences

Good:

- What this decision makes easier or safer.

Bad:

- What it costs, which limits it imposes, and which follow-ups it leaves.

## Alternatives considered

- Only when the spec names alternatives or the trade-off is obvious: each rejected option and why.
