# oxbloom-di v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give `oxbloom-di` trait and collection injection, lifecycle with ordered shutdown, lazy beans, typed bean factories (`.bean`, `#[configuration]`/`#[bean]`) and profile-conditional registrations.

**Architecture:** Replace the `TypeId → provider` map by a typed provider index: every registration is an entry with a concrete key and provided keys (concrete type, `dyn Trait`), modifiers (`primary`, `order`, `lazy`, profile conditions, hooks) and a source label. One resolver serves single, optional and collection shapes. Lazy creation and shutdown share one reentrant container lock. Macros in `oxbloom-macros` generate registrations; `DiError` becomes `#[non_exhaustive]`.

**Tech Stack:** Rust 2024, `syn`/`quote`/`proc-macro2` (already in `oxbloom-macros`), `trybuild` (already a dev-dependency); no new runtime dependency.

**Spec:** `docs/superpowers/specs/2026-10-24-di-v2-design.md`

## Global Constraints

- Crates: `crates/oxbloom-di`, `crates/oxbloom-macros`, small edits in `crates/oxbloom-web`, `crates/oxbloom-config`, `crates/oxbloom-security` (docs/example only). Workspace package fields come from `[workspace.package]`. No new runtime dependency.
- The existing DI tests (`tests/container.rs` 13 tests, `tests/component.rs` 5 incl. the trybuild UI test, `src/error.rs` 4) and the `oxbloom-web --features di`, `oxbloom-config --features di`, `oxbloom-security --features di` tests keep passing; only deliberate `DiError` pattern changes are adapted, and each such change is listed in the task report.
- `DiError` is `#[non_exhaustive]` with these variants: `Missing { requested, required_by }`, `Ambiguous { requested, candidates }`, `Cycle { path }`, `Duplicate { type_name, sources }`, `Creation { type_name, message }`, `Invalid { message }`, `ShutDown`, `TooDeep { limit, path }`. No variant except `Creation.message` carries developer text; no value ever appears.
- Dependency depth limit 256; `TooDeep.path` is truncated to the first 8 entries. Bean arities 0 through 12. Source labels: `component Type`, `instance Type`, `factory Type`, `Type::method` for `#[bean]`, `closure at file:line` for builder beans (use `#[track_caller]`).
- Injectable shapes: `Arc<T>`, `Arc<dyn T>`, `Option<Arc<..>>`, `Vec<Arc<..>>`. A provided trait is `Send + Sync + 'static`.
- A single `Arc<dyn T>` with several providers is `Ambiguous` unless exactly one is `primary`. `Vec` order: `order` then registration order. Profiles: names, any-of (repeated `.profile`), negation (`.profile_not`, `"!x"`); skipped entries are invisible (not candidates, no `Duplicate`, dependency on them is `Missing`).
- Errors are cached per entry (a failed creation returns the same `DiError` forever; the provider is not run again), EXCEPT stack-relative errors: `Cycle` and `TooDeep` are never cached. Stack use: dependency depth 256 must not overflow a 256 KB debug stack for the simplest provider; stack need grows with provider frame size, so Tasks 6 and 7 re-run the stack probe (`probe_stack_for_256_deep_build`, an ignored test in `tests/depth.rs`) and keep hook and lock work out of line (`#[inline(never)]`, no large locals live across the provider call). Panics in providers and `post_construct` hooks are not caught during `build()`; `pre_destroy` panics are caught per hook in `shutdown`.
- No automatic shutdown in `Drop`. After `shutdown()`, every `Container::get*` is `ShutDown`; handles stay valid.
- The repo is not a git repository: no commit steps. Never set `CARGO_TARGET_DIR` or `--target-dir`; `/tmp` is a RAM-backed tmpfs shared with the build target: no new target dirs.
- Public items have runnable doc examples per `AGENT.md`. Brand: "Oxbloom" in prose, "oxbloom" in code.
- Done gate: `cargo fmt --all -- --check`, `cargo clippy --workspace --all-targets`, `cargo test --workspace`, each also with `-p oxbloom-web --features di`, `-p oxbloom-config --features di`, `-p oxbloom-security --all-features`; `cargo build -p hello`; `graphify update .`.

## Review Focus

- A cycle through a trait key (A needs `dyn T` provided by B, B needs A) reports `Cycle` with concrete type names. Pinned in Task 3.
- `Option<Arc<T>>` whose only provider is lazy and fails is an error, never `None`. Pinned in Task 7.
- `shutdown()` called while another thread creates a lazy bean waits and then destroys it (no lost destroy, no deadlock). Pinned in Task 7.
- `Duplicate` is not raised when one of two same-type registrations is profile-skipped. Pinned in Task 5.
- `post_construct` failure cleanup order when a lazy bean was already created earlier. Pinned in Task 6.
- `Container::get` of an eager bean after `shutdown()` is `ShutDown` while previously handed-out `Arc`s still work. Pinned in Task 6.
- A `provides` closure whose type does not match the last registration is `Invalid`, not a panic. Pinned in Task 3.
- `Vec<Arc<dyn T>>` with zero providers is empty; with one provider skipped by profile is empty. Pinned in Task 3 and Task 5.

### Task 7: Lazy beans
