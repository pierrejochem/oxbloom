# C6b-1: JSON bodies and content negotiation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `oxbloom-web` gets `Json<T>`, `Request::json::<T>()` and an `Accept` check that answers 406, all as problem+json errors, behind a default-on Cargo feature `json`; `examples/todos` drops its hand-written JSON helpers.

**Architecture:** `Json<T>` serializes and tags its response with a `JsonBody` extension. A new built-in `JsonNegotiationFilter` at `order::NEGOTIATION = -250` (inside `ERROR_HANDLING`, outside `BODY_LIMIT`) compares the request's `Accept` header with that tag after the handler ran and answers 406 through `HttpError`. `Request::json` checks `Content-Type` (415) and parses the body (400).

**Tech Stack:** Rust, `serde`, `serde_json`, `http`, `bytes`, existing `oxbloom-web` filter chain and `HttpError`.

**Spec:** `docs/superpowers/specs/2026-11-01-web-json-design.md`. The repo is not a git repo: there are no commits. Where a skill says "commit", run the task's verification commands instead.

## Global Constraints

- The Cargo feature is `json`, in `default`. Without it, `Json`, `JsonBody`, `Request::json` and `JsonNegotiationFilter` are not compiled. `order::NEGOTIATION` exists in both builds.
- `order::NEGOTIATION = -250`. Existing constants are unchanged: `REQUEST_LOG -400`, `ERROR_HANDLING -300`, `BODY_LIMIT -200`, `SECURITY -100`, `DEFAULT 0`.
- Status and extension members: 415 carries `accepted = "application/json"`, 406 carries `supported = "application/json"`. 400 `detail` names only the error class (`syntax`, `data`, `eof`) and the line and column, never the body or a value from it.
- A serialization failure answers 500 with no `detail`; the error text is logged at level `error` on target `oxbloom::web` and never sent.
- Every public item has a runnable doc example (`AGENT.md`). Docs, comments and test names are plain full sentences. "Oxbloom" in prose, `oxbloom` in code.
- Stack probes must not grow: boot 238 KB default, 239 KB with `logging`, `build()` frame `sub $0x178,%rsp`, DI 206/277/230/194 KB. No boot code changes.
- Never set `CARGO_TARGET_DIR` or `--target-dir`. Run `graphify update .` after code changes. Use literal absolute paths with `rm`.

## Review Focus

- A `HEAD` request whose `Accept` excludes JSON: the `JsonBody` tag must survive the router's body strip, so the answer is 406, not 200.
- `Accept` oddities: quoted parameter values that contain commas, `q=1.5` or `q=abc` (that range is skipped), upper case, spaces around `;` and `,`, non-UTF-8 header bytes (counts as absent), all-invalid ranges (counts as absent).
- `Content-Type` oddities: `application/json;charset="utf-8"`, a trailing `;`, `APPLICATION/JSON`, `application/jsonx` and `application/json-seq` (must be 415), `+json` without a subtype.
- A body over `server.max-body-bytes` on a JSON route: 413 from the body-limit filter, before `Request::json` and before negotiation of any `Json` answer.
- A handler that returns `Json<T>` for a request the security chain rejects: the 401 problem+json is not turned into 406.
