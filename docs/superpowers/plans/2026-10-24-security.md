# oxbloom-security Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a filter layer to `oxbloom-web` and a new `oxbloom-security` crate with a Spring-style filter chain, deny-by-default authorization and a JWT resource server (static keys and JWKS).

**Architecture:** `App` runs an ordered list of `Filter`s before the router. `SecurityFilterChain` is one such filter: it extracts a bearer token, authenticates through a `ProviderManager`, stores a `SecurityContext` in the request extensions, authorizes against ordered `(RequestMatcher, AuthorizationRule)` pairs, and renders 401, 403 or 503 itself. JWT verification uses `jsonwebtoken`; JWKS keys come from a cached `JwksSource` over a pluggable `JwksFetcher`.

**Tech Stack:** Rust 2024, `jsonwebtoken` 11.1.0, `async-trait` 0.1.92, `serde_json`, `reqwest` 0.13.5 (rustls only, behind feature `jwks`), existing `tokio`/`hyper` stack.

**Spec:** `docs/superpowers/specs/2026-10-24-security-design.md`

**Spec amendment (ruled while planning):** the spec calls `config` an optional feature. `Secret<T>` lives in `oxbloom-config` and appears in core types (`AuthenticationRequest`, `Jwt`), so `oxbloom-config` is a normal dependency and only `jwks` and `di` are cargo features. The spec text is updated to match.

## Global Constraints

- Workspace package fields (`version`, `edition = "2024"`, `license`, `rust-version`) come from `[workspace.package]`.
- New dependency versions, exact: `jsonwebtoken = "11.1.0"`, `async-trait = "0.1.92"`, `reqwest = "0.13.5"` with `default-features = false` and only its rustls feature (name per the 0.13.5 docs; no native-tls or openssl). `serde_json`: latest release at least two weeks old, same version in every crate that uses it. For `jsonwebtoken` choose a crypto-backend feature as its docs require, preferring a pure-Rust backend. Read each crate's own docs before use; do not assume the 10.x API.
- No cryptographic code of our own. Signature work only through `jsonwebtoken`.
- Cargo features of `oxbloom-security`: `jwks` (reqwest fetcher), `di`. Without `jwks` the dependency tree has no HTTP client (verify with `cargo tree`).
- Defaults: clock skew 60 s; JWKS TTL 5 min; JWKS refresh at most once per 30 s; JWKS body cap 1 MiB; JWKS request timeout 5 s; JWKS redirects disabled.
- The token's `alg` header never selects the key type. `alg: none` is always rejected. `exp` is required unless explicitly opted out.
- Unmatched requests are denied. `HasRole("X")` checks authority `ROLE_X`. Scope authorities are `SCOPE_<x>` from `scope` (space-delimited string) or `scp` (array).
- 401: `WWW-Authenticate: Bearer`, plus `error="invalid_token"` for a bad token or `error="invalid_request"` for a malformed `Authorization` header; empty body. 403: empty body. 503 for `ProviderUnavailable`: empty body, no challenge.
- `Display`/`Debug` of every error and of `Jwt`, `Authentication`, `SecurityContext` never contain tokens, keys, claim values or JWKS bodies.
- All tests run offline (loopback only). Public items have doc examples per `AGENT.md`.
- The repo is not a git repository: no commit steps. Done gate: `cargo fmt --all -- --check`, `cargo clippy --workspace --all-targets` and `cargo test --workspace`, each also with `-p oxbloom-security --features jwks`, `--features di` and `--all-features`.

## Review Focus

- Unknown path under an `Authenticated` catch-all returns 401 or 403, never 404. Pinned in Task 5.
- `Authorization: Bearer ` (empty token), two `Authorization` headers, and non-Bearer schemes (`Basic x`): `invalid_request`/anonymous as specified, no panic. Pinned in Task 5.
- `HEAD` on a path permitted only for `GET` is denied (no matching rule), and the router's HEAD fallback does not bypass it. Pinned in Task 4.
- Many requests with random `kid` values cause at most one JWKS fetch per 30 s. Pinned in Task 7.
- Token signed with `none`, or with an RSA public key used as an HMAC secret, is rejected, and the error text contains neither token nor key. Pinned in Task 6.
- Config keys with hyphens cannot be set from environment variable names, so `jwk-set-uri` also accepts `jwk_set_uri`. Pinned in Task 9.
- A filter that returns early never calls the router; a panic in a handler behind the chain does not leave the context of another request visible. Pinned in Task 1 (extensions are per request).
