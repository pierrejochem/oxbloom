# oxbloom-boot (C3a) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add the crate `oxbloom-boot` with `OxbloomApplication`: one entry point that loads config, builds the container, fires lifecycle events, runs startup runners, starts and stops services in order, handles shutdown signals with a deadline and returns an exit status.

**Architecture:** A new crate depends on `oxbloom-config` and `oxbloom-di`. A builder collects arguments, config and container wiring; `run()` executes a fixed sequence of steps, each failure mapped to a `StartupError` with a phase. Long-running work is a `Service` bean (ordered by phase, stopped in reverse under one shared deadline). Events are delivered through the `RunListener` trait, panic-isolated. A cargo feature `web` adds `WebServer`, a `Service` over `oxbloom_web::App`.

**Tech Stack:** Rust 2024, `tokio` (rt, sync, time, signal, macros), `async-trait` (already used in the workspace), `serde` (feature `web` only, for the `server.*` properties), `trybuild` (dev). No new dependency outside crates already in `Cargo.lock`.

**Spec:** `docs/superpowers/specs/2026-10-25-boot-design.md`

## Spec amendments decided while planning

These refine the spec; Task 9 writes them into the spec file.

1. Only a `Service::stop` panic is caught (each stop runs in its own spawned task so a panic is a `JoinError`). Runner and `Service::start` panics still propagate. This resolves the spec's Review Focus 2 against its safety-rules paragraph.
2. `StartupPhase` has `Config`, `Container`, `Runner`, `Service`; no `Shutdown` (nothing produces it). The enum is `#[non_exhaustive]`.
3. `RunListener` methods take their arguments directly (`&Config`, `&Container`, `&ExitStatus`, `&StartupError`); there are no context structs.
4. `RunListener` and `Service` have a provided method `fn name(&self) -> &'static str` (default `std::any::type_name::<Self>()`) so diagnostics can name a `dyn` value.
5. A second signal while stopping returns at once with code 130 (Ctrl-C) or 143 (SIGTERM), fires `stopped`, and skips `Container::shutdown()`.
6. `run_and_exit` maps the code with `clamp(0, 255)`. `ExitCodeGenerator` beans are collected before `Container::shutdown()` (a shut-down container refuses `get_all`) and evaluated after services stop.
7. `WebServer` is a cheap `Clone` handle (inner `Arc`) so a test or listener can keep a clone and read `local_addr()`. The spec's `ServerInfo` bean is dropped.
8. Boot applies its arguments to the `ConfigBuilder` after the user's `config` closure (the builder's `args` replaces, so applying first would let a closure drop them). `stopping` fires on every successful run, also when no service ran (spec step 7 then goes to step 8 with nothing to stop). `oxbloom_boot` re-exports `async_trait` for `Service` and runner impls. `ServiceError::source()` and `RunnerError::source()` return the wrapped error.
9. One signal listener set serves steps 7 and 8 (a quick double Ctrl-C must not lose the second press). Any Ctrl-C or SIGTERM while services stop forces 130/143, including the first one after a `ShutdownHandle` trigger. Tokio's signal handlers stay installed for the rest of the process once a service ran (inherent to tokio; documented). A runtime used with services needs the time and IO drivers.
10. Task order differs from the spec's outline: error types move to Task 2 because `RunListener::failed` needs `StartupError`; `ShutdownHandle` moves to Task 3 because boot registers it as an instance.

## Global Constraints

- Crate `crates/oxbloom-boot`, member of the workspace (`[workspace.package]` fields via `.workspace = true`). Cargo features: `web = ["dep:oxbloom-web", "dep:serde"]`, no default features. Dependencies use the versions already in the workspace: `async-trait = "0.1.92"`, `tokio = "1.54.1"`, `serde = "1.0.229"` (derive), `oxbloom-config`/`oxbloom-di`/`oxbloom-web` by path with `version = "0.1.0"`; dev: `trybuild = "1.0.122"`, `tempfile = "3.27.0"`, `tokio` with `rt`, `macros`, `time`, `net`, `io-util`.
- Public types that may grow are `#[non_exhaustive]`. Every public item has a runnable doc example (`AGENT.md`). Brand: "Oxbloom" in prose, "oxbloom" in code.
- No message produced by boot contains configuration values, argument values or secrets. Allowed content: type names, phase names, counts, the underlying error's own `Display`. `ApplicationArguments` `Debug`/`Display` show counts only.
- `ApplicationArguments` parsing: `--k=v` option (value is everything after the first `=`); `--k` option with value `""`; `--` ends option parsing, everything after is a non-option argument; `--=x` (empty name), `-x` and plain words are non-option arguments; repeated options keep all values in order; `option_names()` lists each name once in first-seen order; names are case-sensitive.
- Run order (spec section "Run order"): 1 parse args, `starting`; 2 config, `environment_prepared`, banner; 3 container with `Config`, `ApplicationArguments`, `ShutdownHandle` instances, `active_profiles(config.active_profiles())`, then `configure` closures in call order, collect listeners, `context_ready`; 4 `ApplicationRunner` then `CommandLineRunner` beans; 5 start `Service` beans ascending `phase` (stable by DI order); 6 `started`, `ready`; 7 wait (skipped if no service started); 8 `stopping`, stop in reverse under one deadline; 9 `Container::shutdown()`; 10 exit code, `stopped`. A failure fires `failed` once, stops started services in reverse, shuts the container down if built, returns `Err(StartupError)`.
- Default `shutdown_timeout` 30 s. Signals installed only while waiting and stopping. No global state: two applications can run in one process.
- The repo is not a git repository: no commit steps. Never set `CARGO_TARGET_DIR` or `--target-dir`; `/tmp` is a RAM-backed tmpfs shared with the build target: no new target dirs. Delete any probe crate you create.
- Done gate: `cargo fmt --all -- --check`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo test --workspace`, each also with `-p oxbloom-boot --features web`, `-p oxbloom-web --features di`, `-p oxbloom-config --features di`, `-p oxbloom-security --all-features`; `cargo build -p hello`; `graphify update .`.

## Review Focus

- A runner that triggers `ShutdownHandle` while a service runs: services stop once, in reverse order (Task 4 test).
- A `stop` that panics: later services are still stopped, the container is still shut down (Task 4).
- Two services with equal phase and `order`: start in registration order, stop reversed (Task 4).
- A `RunListener` bean that depends on a failing lazy bean: `Container`-phase `StartupError`, not a listener panic (Task 3).
- `shutdown_timeout(Duration::ZERO)` with a slow `stop`: abandoned at once, `run()` returns (Task 4).
- A marker value in config, arguments and a secret never appears in `StartupError`, banner output or diagnostics output (Task 7).
