# oxbloom-config Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add the `oxbloom-config` crate, which loads `application.toml`, an optional profile overlay and env overrides, and binds subtrees to serde structs.

**Architecture:** A `Config` wraps a merged `toml::Value`. The builder reads files, merges tables deeply, then applies env overrides as string nodes. `Config::get` deserializes a subtree through a lenient deserializer that parses string leaves into the number or bool the target field expects. An optional `di` feature registers `Config` in `oxbloom-di`.

**Tech Stack:** Rust 2024, `serde` 1.0.229 (derive), `toml` 1.1.8 (both match `oxbloom-cli`), `tempfile` (dev), `oxbloom-di` (optional).

**Spec:** `docs/superpowers/specs/2026-10-24-config-design.md`

## Global Constraints

- Workspace package fields (`version`, `edition = "2024"`, `license`, `rust-version`) come from `[workspace.package]`, as in the other crates.
- `serde` and `toml` versions equal those in `crates/oxbloom-cli/Cargo.toml`.
- Env prefix default is `APP`. Profile env var is `OXBLOOM_PROFILE`. Env path split is on `__`; a single `_` stays in the key name.
- Precedence, highest first: env, `application-{profile}.toml`, `application.toml`.
- Profile names match `[A-Za-z0-9_-]+`.
- No config value ever appears in any `ConfigError` message, `Debug` or `Display`, including `Parse` errors.
- `oxbloom-config` has no dependency on `oxbloom-di` without the `di` feature, and none on `oxbloom-web`.
- All tests avoid the real process environment (use `env_from`) and the network.
- Public items have doc comments.
- Done gate: `cargo fmt --all -- --check`, `cargo clippy --workspace --all-targets` and `cargo test --workspace`, each also with `-p oxbloom-config --features di`, all pass.

## Review Focus

- Env value `"abc"` for a `u16` field: `Invalid { key: "server.port" }`, message without `abc`. Pinned in Task 3.
- Env override on a key that is a table in TOML (`APP_SERVER=x`): `Invalid` on `get`, no panic. Pinned in Task 3.
- `Option<T>` and `Vec<T>` fields next to coerced scalars: untouched, `None` when absent. Pinned in Task 3.
- Empty file and file with only comments: empty config, no error. Pinned in Task 2.
- Profile `"../x"` or empty string: rejected before any file access. Pinned in Task 2.
- Env var `APP_` with an empty path, or `APP_A____B` (empty segment): ignored, no panic. Pinned in Task 2.
- Secret value that fails to parse as TOML in a file: `Parse` message lacks the value. Pinned in Task 4.

- `crates/oxbloom-config/Cargo.toml`: manifest, `di` feature.
- `crates/oxbloom-config/src/lib.rs`: module declarations and re-exports.

- `crates/oxbloom-config/tests/files.rs`, `tests/di.rs`: integration tests.
- Modify `Cargo.toml` (workspace members) and `README.md`.

### Task 3: `Config::get` with the lenient deserializer

**Files:**

- [ ] **Step 1: Write failing tests** in `lenient.rs` and `config.rs`, with `#[derive(Deserialize)]` structs: `string_leaf_coerces_to_u16`, `string_leaf_coerces_to_i64_f64_bool`, `bad_number_is_invalid_naming_key_not_value` (`APP_SERVER__PORT=abc` against `port: u16`: `Invalid { key: "server.port" }`, message does not contain `abc`), `string_field_never_coerced` (`"9000"` stays a string), `nested_struct_coerces`, `option_field_absent_is_none`, `option_field_coerces_when_present`, `vec_field_from_toml_array_untouched`, `vec_of_u16_from_toml_ints`, `missing_required_key_is_missing_naming_key`, `dotted_prefix_binds_subtree`, `empty_prefix_binds_whole_config`, `missing_prefix_is_missing`, `env_string_over_table_node_is_invalid_not_panic`, `secret_field_binds`.
- [ ] **Step 2: Run** `cargo test -p oxbloom-config`. Expected: FAIL.
- [ ] **Step 3: Implement the lenient deserializer** as a wrapper around `toml::Value` that implements `serde::Deserializer`. Its `deserialize_*` methods for integer, float and bool types parse a `Value::String` leaf to the requested type, and every other request delegates to the standard `Value` deserializer. It tracks the key path so errors carry `server.port`-style keys. Map errors to `Invalid { key, message }` with a message built from the serde error kind only, never from the offending value. Map absent required fields to `Missing { key }`.
