# oxbloom-config v2 Implementation Plan

> Note: key names namespaced under `oxbloom.` after the plan was executed.

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give `oxbloom-config` relaxed key matching, list and unit binding, placeholders, command-line and import sources, profile groups, per-value origins, renamed-key migration and introspection.

**Architecture:** Replace the `toml::Value` stored in `Config` by an own `Node` tree whose every node carries an `Origin`; keys are stored by canonical form next to the spelling used by the winning source. All sources (files with imports, profile files, environment, command line) are parsed or applied into `Node` trees and merged, then migration and placeholder passes run, and the lenient deserializer binds directly from `Node`.

**Tech Stack:** Rust 2024, `serde` 1.0.229, `toml` 1.1.8 (its `toml::de::DeTable::parse` gives `Spanned` keys and values, so line numbers come from the parser), no new runtime dependency.

**Spec:** `docs/superpowers/specs/2026-10-24-config-v2-design.md`

## Global Constraints

- Crate: `crates/oxbloom-config`. Workspace package fields come from `[workspace.package]`. No new runtime dependency; `tempfile` stays dev-only.
- Canonical key: lowercase with `-` and `_` removed. Two spellings of one canonical key in the same source are `ConfigError::DuplicateKey { key, first, second }`.
- Source precedence, lowest to highest: `application.toml` (+ its imports), profile files in activation order (+ their imports), environment, command line. Then migration, then placeholders.
- Environment: prefix default `APP`, `__` separates segments, single `_` stays in a segment, a numeric segment is an array index. Command line: `--key=value` only; `.` separates segments; `[n]` or `.n` is an index; an argument without `=` or not starting with `--` is ignored.
- Lists: indices start at 0 without gaps; a higher-precedence list replaces a lower one whole; comma-separated strings split (trim, `\,` escape, empty string = empty list) only when the target is a sequence.
- `Duration` units: `ns`, `us`, `ms`, `s`, `m`, `h`, `d`, fractions allowed, bare number = seconds, negative/overflow/unknown unit = `Invalid`. `DataSize`: `KB MB GB TB` are 1000-based, `KiB MiB GiB TiB` 1024-based, bare number = bytes.
- Placeholders: `${name}`, `${name:default}`, `$${` literal; resolve to config key (canonical match) then environment variable of that exact name; no nested names; nesting depth above 32 is `PlaceholderCycle`.
- Imports: `oxbloom.config.import = ["a.toml", "optional:b.toml"]`, relative to the config dir, no absolute path, no `..`, must stay inside the config dir after resolving symlinks; depth limit 8.
- Profile names match `[A-Za-z0-9_-]+`. Profile preference: `ConfigBuilder::profile` calls, then `--oxbloom.profiles.active=`, then `OXBLOOM_PROFILE` (comma-separated), then `oxbloom.profiles.active` in `application.toml`. `oxbloom.profiles.active` in a profile file is `Invalid`. Groups: `oxbloom.profiles.group.<name> = [..]`.
- No error, warning, `Debug`, `Display` or `explain` output ever contains a configuration value; keys, origins and type names only. `Config`'s `Debug` stays "top-level key names only".
- Public signatures that exist today (`Config::get/from_str/builder`, `ConfigBuilder::dir/profile/env_prefix/env_from/build`, `Secret`, the `di` feature) keep working; `ConfigError::Invalid` gains `origin: Option<Origin>`.
- Public items have doc examples per `AGENT.md`. The repo is not a git repository: no commit steps. Never set `CARGO_TARGET_DIR` or `--target-dir`.
- Done gate: `cargo fmt --all -- --check`, `cargo clippy --workspace --all-targets`, `cargo test --workspace`, each also with `-p oxbloom-config --features di` and `-p oxbloom-security --all-features`.

## Review Focus

- A string with commas bound to a `String` field is never split. Pinned in Task 4.
- A literal `${` in an existing config value now fails with a clear error naming the key; `$${` escapes it. Pinned in Task 6.
- `MAX_CONNECTIONS` in the environment overrides `max-connections` in a file (cross-source), while both spellings in one file is `DuplicateKey`. Pinned in Task 2 and Task 3.
- An import that leaves the config dir (`../x.toml`, absolute path, symlink out of the dir) is rejected. Pinned in Task 5.
- A secret reachable through a placeholder never appears in any error. Pinned in Task 6 and Task 8.
- `--key` without `=`, `--=x`, `--key=` (empty value) and a repeated `--key=a --key=b` (last wins) do not panic. Pinned in Task 3.
- A `Duration` such as `99999999999999999999d` and a `DataSize` that overflows `u64` are `Invalid`, not a panic. Pinned in Task 4.

## File Structure

- `src/origin.rs`: `Origin` and its `Display`.
- `src/node.rs`: `Node`, `NodeValue`, `Table`, `canonical`, merge, TOML-with-spans conversion.
- `src/sources.rs`: environment and command-line application into a `Node`.
- `src/loader.rs`: the load pipeline (files, imports, profiles, groups).
- `src/placeholder.rs`: placeholder resolution.
- `src/migrate.rs`: `ConfigWarning`, the rename/remove registry.
- `src/units.rs`: `DataSize` and the `Duration`/`DataSize` string parsers.
- `src/lenient.rs`: the binder, rewritten over `Node` (existing file).
- `src/config.rs`: `Config`, `ConfigBuilder` (existing), `src/error.rs`: `ConfigError` (existing), `src/lib.rs`: exports.
- Modify `crates/oxbloom-security` (error pattern sites, secret key registration, docs), `README.md`, `docs/API.md`.
