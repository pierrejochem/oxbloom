# oxbloom-cli `new` / `list` Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `oxbloom new <name>` writes a reproducible project that compiles and passes its own test; `oxbloom list` shows component status.

**Architecture:** New crate `crates/oxbloom-cli`. Pure modules (`components`, `naming`, `manifest`, `templates`) do no I/O; `generate` writes files; `cli`/`main` wire clap. The manifest is built from args, then every file is rendered from the manifest value only.

**Tech Stack:** Rust 2024 (toolchain 1.99.1), clap (derive), anyhow, serde, toml, tempfile (dev).

**Spec:** `docs/superpowers/specs/2026-10-23-cli-new-design.md`

## Global Constraints

- Only implemented components are selectable; `--security`, `--database`, `--jobs`, `--ai`, `--tests`, `--frontend` exit non-zero with `<feature> is not implemented yet` and write nothing.
- Name regex `[a-z][a-z0-9_-]*`; target dir must not exist or be empty.
- Manifest tables use `#[serde(deny_unknown_fields)]`; manifest is rendered first, all files derive from it.
- Output deterministic: sorted file order, no timestamps/usernames/random values.
- Exit code 2 for usage errors, 1 for I/O errors; no panics on user input.
- Generated project: edition 2024, `oxbloom-web` path dependency, `tokio` version equal to the workspace `Cargo.lock` at CLI build time.
- Workspace is not a git repo: steps end with a fmt/clippy checkpoint, not a commit. Do not `git init` without asking.
- Report only checks actually run, with real results.

## Review Focus

- Project name equal to a dependency or reserved name (`oxbloom-web`, `tokio`, `test`, `core`, `std`) → rejected with a clear message. Pinned in Task 1.
- `--oxbloom-path` or `--dir` containing spaces, quotes or backslashes → valid TOML in generated `Cargo.toml`. Pinned in Task 3.
- `--oxbloom-path` not pointing at an oxbloom workspace → one-line error, nothing written. Pinned in Task 5.
- `--dir` parent that does not exist → created, not a panic. Pinned in Task 4.
- Target path exists as a regular file → refused, file untouched. Pinned in Task 4.
