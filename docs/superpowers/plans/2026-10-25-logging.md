# C5a Logging and CRUD Example Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add the `oxbloom-logging` crate (levels, groups, runtime change, console format), wire it into `oxbloom-boot` with startup events, and add a new `examples/todos` CRUD API that uses the web, security and logging stack.

**Architecture:** `oxbloom-logging` builds a `tracing` subscriber from `Config` and keeps a reload handle for the level filter. `oxbloom-boot` installs it right after the configuration loads, behind a `logging` feature, and emits `tracing` events at target `oxbloom::boot`. The CRUD example is a new workspace crate that builds JSON by hand, because `Json<T>` belongs to C6.

**Tech Stack:** Rust 1.99.1 (pinned), edition 2024, `tracing 0.1.44`, `tracing-subscriber 0.3.23` (features `fmt`, `env-filter`, `reload`, `ansi`), `tracing-log 0.2.0`, `serde`, `serde_json`, `tokio`.

**Spec:** `docs/superpowers/specs/2026-10-25-logging-design.md`. The CRUD example is not in the spec; it was requested together with the approval (see Task 5).

## Global Constraints

- The repo is not a git repository. There are no commits; tasks end with a passing gate instead. The review package is a snapshot diff.
- Never set `CARGO_TARGET_DIR` or `--target-dir`. `~/.cargo/config.toml` already points cargo at `/tmp/cargo-target`.
- Branding: "Oxbloom" in prose; `oxbloom` in code, crate names and commands.
- AGENT.md: every public item has a runnable doc example.
- Run `graphify update .` after code changes.
- Gate for every task: `cargo test --workspace --all-features`, `cargo clippy --workspace --all-targets --all-features -- -D warnings`, `cargo fmt --check`. The baseline is 1472 workspace tests passing, 441 doc tests.
- Error messages for invalid logging values name the key and never contain the value.
- The stack probe numbers must not rise: 206, 277, 230 and 194 KB, boot 241 KB, `build()` frame `sub $0x178,%rsp`.
- Workspace members: add `crates/oxbloom-logging` and `examples/todos` to the root `Cargo.toml`.

## Review Focus

- A target containing `::` (for example `oxbloom_web::router`): quoted key in TOML, and on the command line `--logging.level.oxbloom_web::router=debug`. Expected: it applies to that module path. Pinned in Task 1.
- A group whose name equals a target name: the group wins and the plain target level is ignored. Pinned in Task 1.
- `logging.level.root=off` with a later `set_level("root", Info)`: logging comes back without a reinstall. Pinned in Task 2.
- A bad value such as `logging.level.x=hunter2`: the report and the error text must not contain `hunter2`. Pinned in Tasks 1 and 3.
- `set_level` called from inside a `tracing` event callback must not deadlock. Pinned in Task 2.
- CRUD: `PUT` on an unknown id is 404 (no upsert), and two concurrent `POST`s never share an id. Pinned in Task 5.

- [ ] **Step 1: Write the failing tests** in `tests/settings.rs` (use `pub` re-exports or `#[doc(hidden)] pub mod __test` if `Settings` stays `pub(crate)`; rule on the least ugly option and note it):

  - `invalid_level_names_key_not_value`: `logging.level.x = "hunter2"` gives `LoggingError::Config(ConfigError::Invalid { .. })` whose text contains `logging.level.x` and not `hunter2`. Same for `logging.console.format`.
  - `static_key_list_is_complete`: a `pub const PROPERTIES: &[(&str, &str, Option<&str>, &str)]` (key, type name, default, description) lists `logging.level.root`, `logging.level.<target>`, `logging.group.<name>`, `logging.console.format`, `logging.console.color`, and every key it names is read by `Settings::from_config` (set each one in a config and see an effect).

### Task 5: Example `examples/todos`, a CRUD API

The request came with the approval of the spec: "create an example api with CRUD operations". Ruling recorded here: it is a new crate, not a change to `hello`, so the `Makefile` finds it (`make run-todos`, `make test-todos`).

**Files:**
- Create: `examples/todos/Cargo.toml`, `application.toml`, `src/lib.rs`, `src/main.rs`, `src/todo.rs` (model and store), `src/api.rs` (controller, `SecurityCustomizer`), `src/json.rs` (helpers), `tests/api.rs`
- Modify: root `Cargo.toml` (member); `crates/oxbloom-boot` unchanged.

**Interfaces:**
- Consumes: `oxbloom-boot` with features `web`, `security`, `logging`; `oxbloom_web::{controller, Request, Response, IntoResponse}`; `oxbloom_di::component`; Task 3's `LoggingSystem` bean (optional use).
- Produces, in the `todos` crate:
  - `pub struct Todo { id: u64, title: String, done: bool }` (serde `Serialize`, `Deserialize`).
  - `pub struct TodoStore` a `#[component]` holding `Mutex<BTreeMap<u64, Todo>>` and an `AtomicU64`; methods `create(title) -> Todo`, `get(id)`, `list(done: Option<bool>)`, `replace(id, title, done) -> Option<Todo>`, `patch(id, title: Option<String>, done: Option<bool>) -> Option<Todo>`, `delete(id) -> bool`. Ids start at 1 and are never reused.
  - `TodoController` with `#[controller("/api/todos")]`: `POST` collection (201, `Location: /api/todos/{id}`, JSON body), `GET` collection (optional `?done=true|false`), `GET /{id}`, `PUT /{id}` (full replace, body `{"title","done"}`), `PATCH /{id}` (any of `title`, `done`), `DELETE /{id}` (204, empty body).
  - Errors are JSON `{"error": "<text>"}`: 400 for unparsable JSON or a non-numeric id, 404 for an unknown id (including `PUT` and `PATCH`, never an upsert), 422 for an empty or whitespace title. Success bodies have `content-type: application/json`.
  - `PublicPaths: SecurityCustomizer`: `/api/todos/**` is `permit_all`, everything else authenticated. Ruling: the example API is open so `curl` works out of the box; a doc comment shows how to require a token for writes with `a.post("/api/todos/**").authenticated()` ahead of the permit rule.
  - `src/json.rs`: `json(status, &impl Serialize) -> Response` and `parse_body<T: DeserializeOwned>(&Request) -> Result<T, Response>`. A comment states that C6 replaces these with `Json<T>`.
  - `pub fn application(config_dir) -> OxbloomApplicationBuilder`, as in `hello`; `main.rs` mirrors `hello`'s.
  - `application.toml`: `[server] port = 8081`, `[logging.level] root = "info"` and `todos = "debug"`.
  - The handlers log with `tracing::info!` on create, update and delete (target `todos`).
  - If the macro rejects an empty route path for the collection, use `"/"` or the path the router normalizes; rule and note it.

- [ ] **Step 1: Write the failing tests** in `tests/api.rs`, in-process on a free port with a `ShutdownHandle`, raw TCP, like `examples/hello/tests/app.rs` (copy its small helpers rather than sharing a crate):
  - `create_returns_201_location_and_body`, `get_returns_created_todo`, `list_returns_all_and_filters_by_done`, `put_replaces_all_fields`, `patch_changes_only_given_fields`, `delete_returns_204_then_get_is_404`, `unknown_id_is_404_for_get_put_patch_delete` (Review Focus 6), `non_numeric_id_is_400`, `bad_json_is_400_with_error_body`, `empty_title_is_422`, `concurrent_creates_get_distinct_ids` (32 parallel `TodoStore::create` calls from threads, unit-level in `src/todo.rs` tests), `unprotected_path_is_401` (`GET /api/other` without a token), `startup_logs_through_oxbloom_logging` lives in its own binary `tests/logging.rs`, because only one app per process can install the global subscriber; every test in `tests/api.rs` builds its app with `.logging(false)`.

- [ ] **Step 3: Implement** the crate. Module docs follow the table style of `examples/hello/src/lib.rs`. Every public item has a doc example that compiles (store methods can use `TodoStore::default()`).
