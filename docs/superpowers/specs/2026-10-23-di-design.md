# oxbloom-di: singleton dependency injection — Design

Date: 2026-10-23
Status: awaiting review

## Purpose

Replace hand-wired `Arc::new(Controller { .. })` state with a small container that builds services and controllers in dependency order, fails at startup (before the server binds) on any wiring mistake, and hands each type out as one shared `Arc<T>`. The crate stays optional: nothing in `oxbloom-core` or `oxbloom-web` requires it unless the `di` cargo feature is enabled.

## Decisions (agreed)

- Runtime container with explicit registration; no compile-time graph proof.
- Singleton lifecycle only. Transient, request scope, init/destroy hooks, `Arc<dyn Trait>` injection and configuration injection are out of scope.
- Controllers are ordinary components. `oxbloom-web` gets an optional `di` feature that resolves a controller from the container and registers its routes.

## Crate `oxbloom-di`

Dependencies: `oxbloom-macros` only (to re-export `#[component]`). No web, no tokio. All managed types must be `Send + Sync + 'static`.

### Public API

```rust
pub trait Component: Sized + Send + Sync + 'static {
    fn create(r: &Resolver) -> Result<Self, DiError>;
}

pub struct ContainerBuilder { .. }
impl ContainerBuilder {
    pub fn new() -> Self;
    pub fn component<T: Component>(self) -> Self;
    pub fn instance<T: Send + Sync + 'static>(self, value: T) -> Self;
    pub fn factory<T, F>(self, f: F) -> Self
        where T: Send + Sync + 'static, F: Fn(&Resolver) -> Result<T, DiError> + Send + Sync + 'static;
    pub fn build(self) -> Result<Container, DiError>;
}

pub struct Resolver<'a> { .. }
impl Resolver<'_> {
    pub fn get<D: Send + Sync + 'static>(&self) -> Result<Arc<D>, DiError>;
}

pub struct Container { .. }              // Send + Sync, cheap to share behind &
impl Container {
    pub fn get<T: Send + Sync + 'static>(&self) -> Result<Arc<T>, DiError>;
}

#[derive(Debug, Clone, PartialEq, Eq)]
pub enum DiError {
    Missing   { requested: String, required_by: Vec<String> },
    Cycle     { path: Vec<String> },
    Duplicate { type_name: String },
    Creation  { type_name: String, message: String },
}
// Display + std::error::Error; type names come from std::any::type_name.
impl DiError {
    /// Builds a `Creation` error for `T` from a user failure message.
    pub fn creation<T: ?Sized>(message: impl Into<String>) -> Self;
}
```

`ContainerBuilder` methods never fail; every error surfaces from `build()`. This keeps the builder chainable.

### Build algorithm

1. Registrations are stored in registration order, keyed by `TypeId`. A second registration of the same `TypeId` is recorded and makes `build()` return `Duplicate` (first duplicate in registration order).
2. `build()` walks registrations in registration order. For each type not yet built it runs the provider with a `Resolver` that tracks an "in-progress" stack.
3. `Resolver::get::<D>()` returns the built `Arc<D>` if present; if `D` is registered but unbuilt it builds `D` first (depth-first), pushing `D` on the stack; if `D` is not registered it returns `Missing` with `required_by` set to the current stack (outermost first).
4. If `D` is already on the stack, `get` returns `Cycle { path }` where `path` runs from the first occurrence of `D` through the stack and back to `D` (for example `A, B, A`). A component that requires itself yields `A, A`.
5. A provider error is returned unchanged if it is already a `DiError`; the `Creation` variant is for errors a user's `factory` or `Component::create` builds from its own failure via `DiError::creation::<T>(message)`.
6. Each type is built exactly once (diamond dependencies share one instance). The resulting build order is deterministic: same registrations, same order.
7. A provider that panics is not caught; the panic propagates out of `build()`. Documented, not handled.

`Container::get::<T>()` never constructs anything: it returns the built `Arc<T>`, or `Missing { requested, required_by: [] }` if `T` was never registered.

### Macro `#[component]`

Lives in `oxbloom-macros`; re-exported as `oxbloom_di::component`. Generated paths are absolute (`::oxbloom_di::...`).

```rust
#[component]
struct UserService { repo: Arc<UserRepo>, mailer: Arc<Mailer> }
// generates:
// impl ::oxbloom_di::Component for UserService {
//     fn create(r: &::oxbloom_di::Resolver) -> Result<Self, ::oxbloom_di::DiError> {
//         Ok(Self { repo: r.get()?, mailer: r.get()? })
//     }
// }
```

Accepted: a struct with named fields (including zero fields) where every field type is a path whose last segment is `Arc` with exactly one generic type argument (`Arc<X>` and `std::sync::Arc<X>`). Rejected with a span on the offending item: tuple and unit-like structs with fields, enums and unions, generic structs, and any field whose type is not `Arc<_>`. Each message names the rule that failed.

## Changes to `oxbloom-macros`

`#[controller]` additionally emits `impl ::oxbloom_web::Controller for <Type>` whose `routes` delegates to the existing inherent `routes`. The inherent method stays, so existing code and tests are unaffected.

## Changes to `oxbloom-web`

- Always available (no feature): `pub trait Controller { fn routes(self: Arc<Self>) -> Vec<Route>; }`, exported from the crate root.
- Cargo feature `di` (off by default) enables the optional dependency on `oxbloom-di` and adds:

```rust
impl App {
    pub fn controller<C: Controller + Send + Sync + 'static>(self, container: &Container)
        -> Result<Self, AppError>;
}
pub enum AppError { Di(DiError), Route(RouteError) }   // Display + Error + From both
```

`controller` resolves `Arc<C>` with `Container::get` and registers `C::routes`. The controller must have been registered with the container (`.component::<C>()`); otherwise the error is `AppError::Di(Missing)`.

## Testing

Unit and integration (in `oxbloom-di`):
- Dependencies are built before dependents; registration order does not matter (register dependent first).
- A diamond (A needs B and C, both need D) builds D once; `Arc::ptr_eq` across all holders.
- `Missing` carries the requested type and the `required_by` chain; unregistered `Container::get` has an empty chain.
- `Cycle` reports `A, B, A` for two components and `A, A` for self-dependence.
- `Duplicate` for a double registration (component + instance of the same type also counts).
- `instance` and `factory` work as dependencies of components; a failing `factory` yields `Creation` naming the type.
- `Container` is `Send + Sync` (compile-time assertion).
- Zero-field component builds.

`trybuild` compile-fail: tuple struct with fields, generic struct, enum, field of a non-`Arc` type (`String`), and field of a different smart pointer (`Rc<X>`).

`oxbloom-web` with `--features di`: a controller component whose field is a service from the container answers a request through `App::handle`; missing registration returns `AppError::Di`; duplicate route returns `AppError::Route`. Without the feature the crate must still build and all existing tests pass (`cargo test -p oxbloom-web` without features).

## Open items

- `Arc<dyn Trait>` injection is the most likely next request; the `TypeId`-keyed design admits it later by registering `Arc<dyn Trait>` as its own key, but this slice does not commit to that.
- The CLI template and `examples/hello` keep their manual wiring until the DI API has settled.
- The directory is not a git repository, so this spec is not committed.
